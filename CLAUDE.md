# CLAUDE.md

Экран мастера для настольных ролевых игр: картинки на «столе», локации,
рисование поверх сцены и кубики. Бэкенда нет, всё состояние живёт в браузере.
Что приложение умеет с точки зрения игрока — в [README.md](README.md).

## Команды

```bash
npm run dev     # дев-сервер, порт 3000
npm run build   # tsc + сборка
npm run lint    # падает на любом предупреждении (--max-warnings 0)
npm test        # vitest run
```

Перед коммитом должны проходить все три: `npm run build`, `npm run lint`,
`npm test`. Тесты покрывают логику, но не мышь и клавиатуру — руками проверяйте
по скиллу `smoke`.

## Структура

```
src/
  components/
    App/            корень: LayerProvider → DrawProvider → сцена
    DragAndDrop/    сцена: картинки, мышь, хранилище
    Canvas/         слой рисования
    LayerModal/     панель локаций
    BrushModal/     панель кисти
    Dice/           кубики
    CursorHalo/     ореол вокруг курсора: детектор тряски мышью
    HelpModal/      справка по горячим клавишам (F1)
    providers/      LayerProvider (локации), DrawProvider (кисть)
    ui/             переиспользуемое: Button, DraggablePanel, ConfirmationModal
    icons/          SVG-иконки через <Icon icon="..." />
  hooks/
    hotkeys/        единая карта горячих клавиш
```

Компонент — это папка: `Component.tsx`, при необходимости `Component.scss`
и `index.ts` с реэкспортом. Алиасы `components/`, `hooks/`, `assets/` заданы
дважды — в `resolve.alias` (сборка) и в `paths` из `tsconfig.json` (типы и
редактор). Меняете один — меняйте оба.

## Состояние и хранилище

Два контекста: `LayerProvider` (список локаций, активная локация, флаг
`isInputActive`) и `DrawProvider` (инструмент, кисть, ref на canvas и сам
рисунок — список штрихов).

Хранилище двухуровневое:

- **localStorage** — метаданные, ключи всегда со суффиксом локации:
  `files-<layerId>` (с версией формата), `background-<layerId>` (id и
  пропорции карты), `viewport-<layerId>`. Плюс `LayersList` и `ActiveLayer`.
- **IndexedDB** (`kapkin-viewer` / `images`) — картинки блобами по id файла и
  рисунок локации списком штрихов по ключу `getDrawingKey(layerId)`. Ключ
  `getCanvasBlobKey(layerId)` — рисунок из старых версий, снимок холста; новых
  таких не появляется.

Главный инвариант: писать можно только в ту локацию, из которой сцена
загружена, и любой новый вид данных локации обязан попасть в
`deleteLayerDataFromStorage` — иначе он останется в хранилище навсегда.
Подробности — в скилле `layer-state`.

## Координаты сцены

У сцены два пространства координат, и путать их нельзя.

**Мир** — это карта локации: прямоугольник в пропорциях фонового изображения
(`viewport.ts`, тип `World`). Положения и размеры картинок хранятся **долями его
ширины** — обе оси меряются одной и той же шириной, поэтому круглый токен
остаётся круглым на карте любой формы. Доли не зависят от пикселей, и сцена
одинаково ложится на монитор любого разрешения: это ответ на «перенёс окно на
телевизор — всё съехало».

**Экран** — то, что даёт мышь. Мир вписывается в экран целиком (`contain`), так
что по одной оси могут остаться поля; их закрывает градиент на
`.drag-and-drop-root`. Связь пространств — `Viewport`:
`screen = worldPx * scale + offset`.

Правила, которые легко нарушить:

- всё, что считает позиции по `e.clientX`, проходит через `screenToWorld`, а
  затем `toFraction`; обратно — `toPixels`, и только при отрисовке
  (`renderImage` в `DragAndDrop.tsx`);
- кламп картинки — `clampToWorld`: токен уходит за край экрана, но не за край
  карты, и нижняя граница по вертикали не единица, а `1 / aspect`;
- размер мира на экране меняют только два события — ресайз окна и новый фон;
  оба ведут в `applyWorld` внутри `useSceneViewport`.

Зум живёт в ref и попадает в CSS-переменные `--scene-scale`, `--scene-x`,
`--scene-y` на корне сцены, минуя React: иначе каждое движение колеса
перерисовывало бы всю сцену. Размер мира, наоборот, обычный стейт — он меняется
редко, зато от него зависит вёрстка. Переменные читают две обёртки
`.scene-layer` — в нижней фон и боевая карта, в верхней токены. Разрезаны они
потому, что между картой и токенами стоят рисунок и сетка.

Кому нужно знать о зуме, но не через CSS (холст рисования), подписывается через
`subscribeViewport`.

## Рисунок

Рисунок хранится не картинкой, а **штрихами**: точки в долях ширины карты, цвет,
толщина (тоже доля), прозрачность и признак ластика (`render-drawing.ts`).
Поэтому он переживает и смену разрешения, и зум — на каждом кадре собирается
заново, а не растягивается.

Холст при этом **экранный**: он растянут на окно и не трансформируется, карту к
нему приводит трансформация контекста (`applyWorldTransform`). Отсюда чёткость
при любом приближении — штрихи рисуются в разрешении экрана, а не карты.

Что из этого следует для правок:

- перерисовка полная и идёт через `renderDrawing`; порядок штрихов важен, иначе
  ластик перестанет стирать нарисованное до него;
- перерисовку заказывают только через `scheduleRedraw` (кадры коалесцируются
  через `requestAnimationFrame`);
- изменили рисунок — дёрните `bumpDrawing`: по этой версии холст
  перерисовывается, а `useSyncCanvas` сохраняет;
- рисунок из старых версий (снимок холста) подкладывается под штрихи и исчезает
  вместе с очисткой холста.

## Версии данных

**Сцена.** `files-<layerId>` хранится как `{ version, files }`. Версия 1 —
голый массив с пикселями; при гидрации он переводится в доли
(`migrateFilesToFractions`) и тут же пересохраняется. Меняете смысл координат —
поднимайте `FILES_VERSION` и пишите перевод там же.

**Рисунок.** `DRAWING_VERSION` у списка штрихов — на будущее: битые штрихи
отсеиваются при чтении (`isStroke`), а не роняют отрисовку.

## Горячие клавиши

Все клавиши объявлены в `src/hooks/hotkeys/keymap.ts`, обработчики вешаются
через `useHotkeys`. Два правила, которые проверяются тестами: буквенная клавиша
объявляется в обеих раскладках, и по умолчанию хоткей молчит, пока фокус в поле
ввода. Справка по F1 (`HelpModal`) строит список клавиш из той же карты, а
клавиши в поле ввода и мышь перечислены в ней вручную — меняете их, правьте
справку. Подробности — в скилле `hotkey`.

## Стиль кода

- SCSS в духе БЭМ: `block__element`, состояния через `is-active` / `is-editing`.
  Каркас плавающих панелей — в `DraggablePanel.scss`, модификатор конкретной
  панели пишется двойным классом (`.draggable-panel.layer-modal`), чтобы не
  зависеть от порядка склейки стилей.
- `styled-components` — только для позиционирования сцены (`StyledComponents.ts`),
  transient-пропсы с `$`.
- Тексты интерфейса — по-русски, имена в коде и `aria-label` — по-английски.
- `void promise` помечает запись в IndexedDB, за результатом которой не следят.
- Комментарии объясняют «почему», а не «что»; пишутся по-русски.
