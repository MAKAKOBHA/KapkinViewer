# Данные, живущие внутри локации

Сцена целиком принадлежит активной локации: переключение `activeId` заново
собирает картинки, фон и рисунок. Поэтому у каждого вида данных есть четыре
обязанности — тип, загрузка, сохранение и удаление. Забыть можно любую, и чаще
всего забывают удаление: потерянные блобы в IndexedDB никак себя не проявляют,
пока хранилище не переполнится.

## Где что лежит

| Что | Где | Ключ |
| --- | --- | --- |
| Метаданные картинок | localStorage | `files-<layerId>` |
| Id фона | localStorage | `background-<layerId>` |
| Список локаций | localStorage | `LayersList` |
| Активная локация | localStorage | `ActiveLayer` |
| Блобы картинок | IndexedDB `kapkin-viewer` / `images` | id файла |
| Рисунок канваса | IndexedDB, там же | `getCanvasBlobKey(layerId)` |

Правило: в localStorage — только то, что переживёт `JSON.stringify`. Картинки,
рисунок и вообще любые бинарные данные — блобами в IndexedDB, а в localStorage
лежит лишь ссылка на ключ.

## Что сделать, добавляя новый вид данных

1. **Тип и ключ.** Функции чтения/записи — в `src/components/DragAndDrop/storage.ts`,
   рядом с существующими. Ключ обязательно со суффиксом локации:
   `` `${LS_MY_THING_KEY}-${layerId}` ``. Читающая функция не должна падать на
   мусоре в хранилище: оберните `JSON.parse` в `try/catch` и верните пустое
   значение.
2. **Загрузка.** В `useSyncFilesWithStorage` (или в своём хуке по его образцу).
   Ключевой инвариант: **писать можно только в ту локацию, из которой сцена
   загружена.** В хуке это выражено через `hydratedId === activeId` — между
   сменой локации и концом гидрации в состоянии ещё лежат данные предыдущей, и
   сохранить их под новым ключом значит затереть чужое.
3. **Сохранение.** Только при `isSynced`, с дебаунсом, если пишется часто.
4. **Удаление.** Добавьте ключ в `deleteLayerDataFromStorage` — и в localStorage,
   и в IndexedDB. **Это тот шаг, который забывают.**

## Если данные бинарные

Блоб в IndexedDB показывается через object URL, а каждый такой URL держит память,
пока его не отозвали. Реестр — `src/components/DragAndDrop/preview-urls.ts`:

- `createPreviewUrl(id, blob)` — создать (старый URL этого id отзывается сам);
- `revokePreviewUrl(id)` — при удалении объекта со сцены;
- `revokePreviewUrlsExcept(ids)` — после гидрации, чтобы убрать превью прошлой
  локации.

Ключ реестра — **id объекта, а не сам URL**: у дубликата картинки свой id и свой
URL, иначе удаление оригинала погасило бы копию.

Никогда не зовите `URL.createObjectURL` напрямую в компонентах — только через
реестр.

## Чек-лист перед тем, как считать готовым

- [ ] Ключ в localStorage содержит `layerId`.
- [ ] Чтение переживает испорченный JSON.
- [ ] Запись не происходит, пока сцена не загружена (`isSynced`).
- [ ] Ключ добавлен в `deleteLayerDataFromStorage`.
- [ ] Бинарные данные проходят через `preview-urls.ts`.
- [ ] Тест в `storage.test.ts`: данные двух локаций не смешиваются, а удаление
      одной локации не задевает соседнюю.
- [ ] Руками: создать две локации, наполнить обе, перезагрузить страницу,
      переключиться туда-обратно, удалить одну и проверить, что вторая цела
      (скилл `smoke`).
